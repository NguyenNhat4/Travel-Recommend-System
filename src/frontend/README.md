# V-OTA frontend

Next.js App Router frontend for the V-OTA travel application. Assistant requests are streamed through the same-origin Next.js BFF to the FastAPI backend; assistant conversations are not served by the local Express health server.

## Run Locally

Setup and run commands live in the [root README](../../README.md) (`make web` starts FastAPI and Next.js together). This file only describes frontend-specific details.

Auth goes through the Next.js BFF (`src/app/api/auth/*`, logic in `src/services/server/`): the browser only holds the HttpOnly `vota_sid` cookie and the readable `vota_csrf` cookie, never a token. Set `AUTH_SERVICE_TOKEN` to the same value as the backend and `SESSION_REDIS_URL` to the Redis from `docker compose up -d redis` (empty = in-memory store, dev only). All browser requests go through `src/services/http.ts` (`apiFetch`), which adds `X-CSRF-Token` on writes. Spec: `docs/spec/hop-dong-tich-hop-auth.md`.

Cart, checkout and booking pages call `/api/v1/cart*` and `/api/v1/bookings*` through the same BFF (`src/services/booking.ts`). `/checkout` has three steps (Hành khách → Dịch vụ → Xem lại và thanh toán, `?step=`): all state lives in `src/components/checkout/useCheckout.ts`, the validation rules in `checkoutRules.ts` mirror the backend's `party_rules.py` and run the same shared cases (`src/shared/contracts/tests/booking-rules-cases.json`), and every money figure comes from `CartResponse`/`BookingResponse` (the web never adds prices; `fareEstimate.ts` is display-only). Spec: `docs/spec/booking/checkout-nhieu-buoc-hanh-khach.md`. Unit tests: `node_modules/.bin/vitest run`. Pressing **Thanh toán** creates a 30-minute hold and redirects the browser to Stripe Checkout (test mode); the backend needs the Stripe variables from `src/backend/README.md` (§Booking và thanh toán Stripe). Stripe returns to `/booking/{referenceCode}?payment=return`, which polls the booking until the webhook confirms it.

The optional `npm run dev:api` process serves the independent Express health endpoint on port 3001. It is not an assistant backend. Regenerate OpenAPI types with `npm run generate:api-types` after contract updates.

Catalog data comes only from the API (`src/services/catalog.ts`: `/products`, `/products/{id}`, `/products/{id}/similar`, `POST /events`); there is no local product catalog. Hotels (`level: property`) and flight routes (`level: route`) are view-only — the product page lists their rooms/flights via `GET /products?parentProductId=` and adds the chosen one to the cart. Missing images use `public/placeholders/<taxonomy>.svg`.

Fonts: headings and navigation use Cal Sans (single weight, so `font-synthesis-weight: none`), body text uses Inter; both load from the Google Fonts `<link>` in `app/layout.tsx`, tokens and the `type-hero`/`type-title` scale live in `app/globals.css`. Header control sizes live in `components/layout/nav/headerStyles.ts`. The assistant is only the floating widget (`features/itinerary/widget`); open it from anywhere with `useAssistant().openFloatingWidget(message?)`.

Category pages (`/hotels`, `/flights`, `/experiences`, `/combos`) are one template, `src/features/catalog/landing/VerticalLanding.tsx`, driven by `verticals.ts`. To add a category: add an entry to `verticals.ts` and to `components/layout/nav/navConfig.ts` (header menus, mobile chips, Home tiles and footer all read it), and a `page.tsx` that passes the URL's `destination`/`type` to `VerticalLanding`. Below-the-fold sections load only when scrolled near (`hooks/useInView.ts`, `hooks/useLazySection.ts`; the latter caches public catalog data for 60 s and is cleared when the account changes). Search-sheet dates and party size travel in the URL as trip context (`features/search/tripContext.ts`) and prefill the booking box; the backend does not filter by date. Spec: `docs/spec/hop-dong-tich-hop-frontend.md` §4.1a; plan: `docs/plan/2026-09-29-ui-trang-danh-muc-va-header.md`.

`/search` (`components/search/`): tab Tất cả · Lưu trú · Tour và trải nghiệm · Tiện ích khác, không có vé máy bay và không có bộ lọc điểm đến. "Tất cả" là các hàng cuộn ngang (`GroupShelf`, `HScroller`) chỉ lấy 6 mục đầu mỗi nhóm; tab nhóm (`GroupResults`) mới tải danh sách đầy đủ, mọi trang đều qua bộ đệm `useLazySection`/`loadSection`. Sắp xếp là popup (`SortMenu`). Spec: `docs/spec/hop-dong-tich-hop-frontend.md` §4.2.

`/flights` (`features/flights/`): tìm vé máy bay ngay tại trang. Hero và tấm tìm kiếm ở trên; bấm Tìm thì chuyến bay hiện luôn bên dưới (`FlightsPage`, URL cập nhật bằng `history.replaceState`), chưa nhập đủ điểm đi và điểm đến thì bên dưới nhắc nhập; không có khối "phổ biến" và "giá tốt". Dữ liệu chỉ từ `GET /products` (`services/flights.ts`: tuyến theo điểm đến, chuyến theo `parentProductId`); `results/flightModel.ts` gom hạng vé thành một thẻ mỗi hành trình, lọc theo buổi/hãng/điểm dừng, gom ngày và ghép chặng đi–về; "Đặt vé" thêm từng chặng vào giỏ. Spec: `docs/spec/hop-dong-tich-hop-frontend.md` §4.1b.
